# Mirrors PC-8801 MC 원본 CD 이미지 분석

분석 대상은 `reference/Original/Mirrors.img` 및 같은 이름의 `.ccd`·`.sub` 파일이다. 이 문서는 정적 파일 구조 분석 결과이며, 에뮬레이터나 게임 실행으로 검증한 내용은 포함하지 않는다.

## 1. 분석 대상과 식별값

| 파일 | 크기 | MD5 |
|---|---:|---|
| `Mirrors.img` | 551,779,200 bytes | `84E583EC62372CA9DD0D737DCE38B5D8` |
| `Mirrors.ccd` | 3,500 bytes | `80273154A2DAF2D107A282B353A86246` |
| `Mirrors.sub` | 22,521,600 bytes | `E45923398B1D150F71E6056BD0974D15` |

CloneCD 형식의 단일 세션 CD이며, raw `.img`는 2352-byte 섹터 234,600개로 구성된다. `.sub`는 섹터당 96-byte 서브채널 데이터다.

## 2. 트랙 구성

| 트랙 | 시작 LBA | 종류 | 비고 |
|---:|---:|---|---|
| 1 | 0 | CDDA | 오디오 |
| 2 | 13,350 | MODE1/2352 | 게임 데이터 |
| 3~15 | 33,300부터 | CDDA | 게임 음악 |

Track 2의 CUE상 영역은 LBA 13,350~33,299(19,950 raw 섹터)다. 이 중 LBA 33,150~33,299는 Track 3의 150-sector(2초) 프리갭으로, raw 데이터와 Q 서브채널 모두 프리갭임을 나타낸다. 따라서 실제 Track 2 MODE1 사용자 데이터는 LBA 13,350~33,149의 19,800섹터, 총 `0x26AC000`(40,550,400 bytes)다.

Track 2 사용자 데이터는 각 raw 섹터의 24-byte 지점부터 2048 bytes다. 논리 데이터 오프셋을 raw 파일 위치로 바꿀 때는 다음을 사용한다.

```text
lba        = 13350 + (logical_offset / 0x800)
raw_offset = lba * 2352 + 24 + (logical_offset % 0x800)
```

## 3. Track 2 상단 프로그램 영역

Track 2 논리 오프셋 기준이다.

| 오프셋 | 크기 | 내용 |
|---:|---:|---|
| `0x0000` | - | CD 식별 문자열 및 부트 관련 데이터 |
| `0x1000` | `0x0800` | `asminit1` (로드 `0xD100`) |
| `0x1800` | `0x0800` | `asminit2` (로드 `0xD800`) |
| `0x2000` | `0x0286` | intro BASIC |
| `0x2800` | `0x0800` | `asmsub` (로드 `0x7B00`) |
| `0x3000` | `0x1000` | `asmbasic` (로드 `0x9000`) |
| `0x4000` | `0x0800` | `asm3` (로드 `0xB310`) |
| `0x4800` | `0x2800` | `asmmain` (로드 `0xA300`) |
| `0x8000` | `0x34C6` | menu BASIC |
| `0xA800` | `0x0800` | `asm5`로 표기된 영역, menu BASIC 범위와 겹침 |
| `0xF000` | `0x0400` | `snddat` |
| `0xF800` | - | CD 내장 2D 플로피 이미지 시작 |

`asm5`의 주소 범위는 menu BASIC 범위와 겹친다. 따라서 이 영역을 독립 실행 ASM이라고 단정하지 않고, 실제 로딩·호출 경로를 추가 분석해야 한다.

## 4. CD 내장 플로피 데이터

원본은 1024-byte 섹터 400개, 즉 `0x64000` bytes인 2D 플로피 이미지를 CD Track 2에 직접 배치한다.

- 유효 이미지: 53개
- 배치: `main`, `disk01`~`disk43`, `disk44`~`disk52`
- `disk44`~`disk52`는 논리 슬롯 63~71에 배치된다.
- 그 외 슬롯은 모두 0으로 채워져 있다.
- 모든 유효 플로피에서 확인된 파일 디렉터리 항목: 1,735개
- 시나리오 BASIC: 134개 항목, 이름 기준 105종

원본 외부 D88 이미지와의 대조 결과:

| 외부 D88 | CD 내장 이미지와의 관계 |
|---|---|
| Disk 1 - Main disk | CD `main`과 바이트 단위 동일 |
| Disk 2 - Game disk | CD `disk01`과 바이트 단위 동일 |
| Disk 3 - Save disk | CD 내에 동일 이미지 없음 |

각 D88은 80트랙, 1024-byte 섹터 400개(416,688 bytes)로 구성된다.

## 5. 시나리오 디스크 로딩

원본 menu BASIC의 `COMMON COPY &H01, sector` 호출을 정적으로 조사했다.

- 호출 92개, 대상 43종
- 직접 대상: `disk01`~`disk12`, `disk22`~`disk43`, `disk44`~`disk52`
- 관찰된 로딩 순서: `disk01`~`disk12` → `disk44`~`disk52` → `disk22`~`disk43`
- `disk13`~`disk21`은 CD에 존재하지만, menu BASIC의 직접 `COMMON COPY` 대상에는 없다.

`disk15`~`disk21`은 각각 `disk46`~`disk52`와 바이트 단위로 중복된다. 이 사실은 디스크 번호만으로 런타임 필요 여부를 판단하면 안 된다는 뜻이며, 실제 호출 경로를 기준으로 판단해야 한다.

## 6. 원본에서 확인된 0 채움 영역

실제 MODE1 사용자 데이터 범위에서 연속 0-byte 영역은 다음 두 곳이다.

| 논리 오프셋 범위 | 크기 | 섹터 수 |
|---|---:|---:|
| `0x113F800`~`0x18AB7FF` | `0x76C000` | 3,800 |
| `0x1C2F800`~`0x26ABFFF` | `0xA7C800` | 5,369 |
| 합계 | `0x11E8800` (18,778,112 bytes, 약 17.91 MiB) | 9,169 |

이 영역은 바이트 스캔상 0으로 채워져 있고, menu BASIC의 직접 `COMMON COPY` 대상도 아니다. 다만 ASM의 직접 섹터 참조 가능성은 아직 완전히 배제하지 않았으므로, 한글 데이터를 배치할 안전 영역으로 확정하기 전에는 ASM·로더 참조를 추가 확인해야 한다.

## 7. 한글화 작업에 주는 제약

- CD에 새 글꼴·문자열 데이터를 넣을 물리 공간은 원본 기준으로 존재한다.
- 그러나 실제 사용 가능 여부는 BASIC뿐 아니라 ASM과 디스크 로더의 직접 참조까지 확인한 뒤 결정한다.
- CloneCD raw 이미지에 직접 기록할 때는 2352-byte 섹터 구조와 Track 3 프리갭을 보존해야 한다.
- 원본 플로피 배치와 영문 패치의 재패킹 구조는 별도로 비교·확정해야 한다. 비교 결과와 아직 확정되지 않은 사항은 다음 절에 기록한다.

## 8. 영문 패치 소스·배포 이미지와의 비교

비교 대상:

| 대상 | 위치 | 식별값 |
|---|---|---|
| 영문 패치 소스 | `reference/mirrors_tools` | Ruby 빌드 도구와 Import/Export 자료 |
| 영문 배포 이미지 | `reference/Mirrors PC-8801 MC English translation v1.0 (updated emu)/Mirrors eng v1.0.img` | MD5 `F3BC8D9E2650D9D9C6EBAEF5E2353144` |

영문 배포 IMG의 크기는 원본과 같은 551,779,200 bytes다. 원본과 raw 섹터 단위로 비교하면 9,453섹터가 다르다.

| 범위 | 변경 raw 섹터 수 | 판정 |
|---|---:|---|
| Track 1 끝 LBA 13,125~13,349 | 225 | Track 2 앞의 프리갭/이미지 패키징 변경 |
| Track 2 데이터 | 9,228 | 프로그램, 글꼴, 시나리오 저장 구조 변경 |
| Track 3~15 CDDA | 0 | 음악 데이터는 바이트 단위 동일 |

즉 영문 패치는 음악을 변경하지 않고, Track 2와 Track 2 진입부의 디스크 레이아웃만 바꾼다.

### 8.1 소스가 명시한 고정 패치 영역

영문 소스의 `Data/i_cddata.csv`와 `Ruby/DataImporter.rb`는 아래 영역을 생성·삽입한다. 주소는 Track 2 논리 오프셋이다.

| 영역 | 오프셋 | 예약 크기 | 역할 |
|---|---:|---:|---|
| `asminit2` | `0x01800` | `0x0800` | 초기화 ASM 수정 |
| `asmsub` | `0x02800` | `0x0800` | 서브 루틴 ASM 수정 |
| `asmbasic` | `0x03000` | `0x1000` | BASIC 연동 ASM 수정 |
| `patch_copy` | `0x03980` | `0x0380` | CD 복사 처리 패치 |
| `asmmain` | `0x04800` | `0x2800` | 메인 ASM 수정 |
| `vwf` | `0x10000` | `0x1000` | 영문 VWF 출력 루틴 |
| script font | `0x11000` | `0x0C00` | 대사 글꼴 데이터 |
| script widths | `0x11F20` | `0x0060` | 대사 글꼴 폭 테이블 |
| UI font | `0x12000` | `0x0C00` | UI 글꼴 데이터 |
| UI widths | `0x12F20` | `0x0060` | UI 글꼴 폭 테이블 |
| menu font | `0x13000` | `0x0C00` | 메뉴 글꼴 데이터 |
| menu widths | `0x13F20` | `0x0060` | 메뉴 글꼴 폭 테이블 |

추가로 intro BASIC(`0x2000`)과 menu BASIC(`0x8000`)을 다시 컴파일하여 삽입한다. 원본의 `asminit1`과 CDDA 음악 트랙은 이 변경 목록에 없다.

### 8.2 시나리오 저장 방식의 차이

원본은 53개의 2D 플로피 이미지(`0x64000` bytes)를 CD에 개별 배치한다. 영문 소스는 이들 중 런타임에 사용하는 이미지를 최대 3개씩 2HD 크기(`0x12C000` bytes)로 묶어 Track 2의 새 위치에 패킹하고, menu BASIC의 `COMMON COPY` 주소표와 서브디스크 번호를 함께 고친다.

소스의 재패킹 대상은 `main`과 `disk01`~`disk15`의 16개 그룹이며, 그룹 안에 원본의 `disk01`~`disk52`를 서브디스크 0~2로 배치한다. 따라서 영문판의 시나리오 로딩 구조는 원본의 개별 2D 배치와 다르다.

### 8.3 소스와 배포 이미지의 재현성 상태

소스에는 ASM 소스, Ruby 빌드 규칙, CSV 주소표, PNG 글꼴 원본이 있으나, 배포 영문 이미지를 그대로 재생성하는 데 필요한 모든 중간 산출물은 포함되어 있지 않다. 특히 다음은 현재 참조 트리에 없다.

- 추출된 원본 Track 2 파일 `02 MIRR.iso`
- 빌드 후 생성되는 `Import/ASM/*.raw`
- 재구성된 플로피 및 파일 트리

또한 소스가 기록한 2HD 그룹 식별 바이트의 예상 위치는 현재 확보된 배포 이미지에서 그대로 확인되지 않았다. 따라서 다음 결론으로 관리한다.

1. 영문 소스가 설명하는 변경 방향(VWF 추가, 세 글꼴 뱅크, BASIC/ASM 교체, 시나리오 재패킹)은 배포 이미지의 대규모 Track 2 변경과 부합한다.
2. 현재 참조 소스가 배포된 영문 이미지와 바이트 단위로 완전히 같은 빌드인지에는 아직 증거가 부족하다.
3. 한글판 제작 전에 배포 영문 이미지에서 실제 menu 로더 주소표와 2HD 묶음의 디렉터리를 직접 추출하여, 실제 런타임 배치를 확정해야 한다.

### 8.4 한글화 기준점

한글화는 원본의 개별 2D 플로피 배치를 직접 수정하는 방식보다, 영문 패치의 VWF·BASIC/ASM·시나리오 재패킹 구조를 기준으로 진행해야 한다. 다만 영문 소스의 주소표를 그대로 신뢰해 기록하는 단계와, 배포 영문 이미지의 실제 바이트·로더를 검증하는 단계는 구분해야 한다.
