# Mirrors PC-8801 MC 원본 CD 이미지 분석

분석 대상은 reference/Original/Mirrors.img와 같은 세트의 .ccd, .cue, .sub, D88 이미지다. 이 문서는 raw 파일·Track 2 논리 데이터·내장 플로피·D88을 정적으로 비교한 결과다. 에뮬레이터나 게임 실행은 사용하지 않았다.

## 1. 분석 대상과 식별값

| 파일 | 크기 | MD5 |
|---|---:|---|
| Mirrors.img | 551,779,200 bytes | 84E583EC62372CA9DD0D737DCE38B5D8 |
| Mirrors.ccd | 3,500 bytes | 80273154A2DAF2D107A282B353A86246 |
| Mirrors.cue | 623 bytes | - |
| Mirrors.sub | 22,521,600 bytes | E45923398B1D150F71E6056BD0974D15 |

Mirrors.img는 CloneCD raw 형식이며 2352-byte 섹터 234,600개로 구성된다. .sub 크기는 234,600 × 96으로 raw 섹터 수와 일치한다. CloneCD 메타데이터는 단일 세션, 15개 트랙, Track 2만 MODE1 데이터로 기록한다.

|---:|---:|---:|---|---:|
| 1 | 0 | 13,350 | CDDA | 2:58 |
| 2 | 13,350 | 19,950 | MODE1/2352 | 4:26 |
| 3 | 33,300 | 35,850 | CDDA | 7:58 |
| 4 | 69,150 | 3,150 | CDDA | 0:42 |
| 5 | 72,300 | 14,475 | CDDA | 3:13 |
| 6 | 86,775 | 15,525 | CDDA | 3:27 |
| 7 | 102,300 | 9,600 | CDDA | 2:08 |
| 8 | 111,900 | 8,025 | CDDA | 1:47 |
| 9 | 119,925 | 10,425 | CDDA | 2:19 |
| 10 | 130,350 | 18,075 | CDDA | 4:01 |
| 11 | 148,425 | 12,825 | CDDA | 2:51 |
| 12 | 161,250 | 23,175 | CDDA | 5:09 |
| 13 | 184,425 | 11,700 | CDDA | 2:36 |
| 14 | 196,125 | 24,375 | CDDA | 5:25 |
| 15 | 220,500 | 14,100 | CDDA | 3:08 |

Track 2의 CUE상 raw 범위는 LBA 13,350–33,299이다. 실제 MODE1 섹터는 LBA 13,350–33,149이며, LBA 33,150–33,299의 150 raw 섹터는 전부 0으로 채워진 Track 3 직전 영역이다.

실제 논리 데이터는 다음과 같다.

~~~text
논리 섹터 수 = 19,800
논리 섹터 크기 = 2048 bytes
논리 데이터 크기 = 40,550,400 bytes = 0x26AC000
SHA-256 = e53f8331c3b3670dcc26b8e7f3762915a3e62014858221e9c9575e5cbc180188
~~~

CloneCD MODE1 raw 섹터에서 사용자 데이터는 섹터 시작 후 +16 바이트에 있다. +24가 아니다.

~~~text
lba        = 13350 + (logical_offset / 0x800)
raw_offset = lba * 2352 + 16 + (logical_offset % 0x800)
~~~

Track 2는 표준 ISO9660 파일시스템이 아니라 NEC PC-8801 전용 CD Type1 데이터다. 논리 데이터의 첫 96바이트에는 다음 식별 문자열이 있다.

~~~text
NEC Personal Computer PC-8801 Series CD Type1
**** Soft stadio WING ** MIRRORS PC88 ******
~~~

## 3. Track 2 상단 프로그램 영역

오프셋은 Track 2의 2048-byte 논리 데이터 기준이다.

| 오프셋 | 크기 | 내용 | 로드 주소 |
|---:|---:|---|---:|
| 0x0000 | 0x1000 | CD 식별 헤더와 부트/로더 영역 | - |
| 0x1000 | 0x0800 | asminit1 | 0xD100 |
| 0x1800 | 0x0800 | asminit2 | 0xD800 |
| 0x2000 | 0x0286 | intro BASIC | - |
| 0x2800 | 0x0800 | asmsub | 0x7B00 |
| 0x3000 | 0x1000 | asmbasic | 0x9000 |
| 0x4000 | 0x0800 | asm3 | 0xB310 |
| 0x4800 | 0x2800 | asmmain | 0xA300 |
| 0x8000 | 0x34C6 | menu BASIC | - |
| 0xA800 | 0x0800 | asm5 | 0x9D00 |
| 0xF000 | 0x0400 | snddat | - |
| 0xF800 이후 | - | CD 내장 2D 플로피 이미지 | - |

menu BASIC은 0x8000–0xB4C5, asm5는 0xA800–0xAFFF이므로 물리 데이터 범위가 겹친다. asm5를 별도 복사본으로 계산하면 안 된다.

e_cddata.csv 기준으로 상단 영역에는 BASIC 2개, ASM 7개, raw 사운드 데이터 1개가 정의되어 있다. CSV에 없는 0x0000–0x0FFF는 CD 부트/로더 영역으로 확인된다.

## 4. CD 내장 2D 플로피 전체 배치

각 이미지는 1024-byte 섹터 400개로 구성된 0x64000 bytes 2D 이미지다.

| 이미지 그룹 | 첫 오프셋 | 마지막 오프셋 | 비고 |
|---|---:|---:|---|
| main | 0x00F800 | - | 메인 디스크 |
| disk01–disk12 | 0x073800 | 0x4BF800 | 0x64000 간격 |
| disk13–disk21 | 0x523800 | 0x843800 | 소스 CSV 누락 구간 |
| disk22–disk43 | 0x8A7800 | 0x10DB800 | 0x64000 간격 |
| disk44–disk52 | 0x18AB800 | 0x1BCB800 | 0x64000 간격 |

따라서 원본 CD에 실제로 존재하는 내장 플로피는 다음 53개다.

~~~text
main + disk01–disk52 = 53개
~~~

reference/mirrors_tools/Data/e_cddata.csv는 disk13–disk21을 등록하지 않았다. 0x523800–0x8A77FF는 빈 공간이 아니라 9개의 정상적인 2D 이미지다.

disk13–disk21과 후반의 disk44–disk52는 중복 보관본이다. 따라서 이 영역은 빈 더미 영역은 아니지만, 독립적인 게임 디스크를 추가로 제공하기 위한 데이터라기보다 Track 2의 고정 디스크 슬롯을 채우고 원본 CD의 물리 배치를 유지하는 중복 영역으로 보는 것이 타당하다. 정확한 제작 의도는 원본 소스에 기록되어 있지 않으므로 이 부분은 디스크 내용 비교에 근거한 구조적 판단이다.

- disk15–disk21은 각각 disk46–disk52와 바이트 단위로 동일하다.
- disk13–disk14는 디렉터리가 동일하고 일부 후반/미사용 섹터만 다르다.
- 따라서 CSV가 해당 9개를 제외한 것은 물리 이미지가 없어서가 아니라, 소스가 중복 보관본을 논리 패치 대상으로 사용하지 않기 때문으로 판단된다.
- disk13–disk21 전체는 9 × 0x64000 = 0x384000 bytes이며, 2HD 이미지 3개와 같은 크기다. 용량이 부족할 때는 이 중복 슬롯을 추가 2HD 그룹으로 재활용할 수 있지만, 단순히 데이터를 덮어쓰는 것으로 끝나지 않는다. Track 2 주소와 디스크 디렉터리, 패킹 표를 함께 갱신해야 한다.

## 5. 2D 플로피 내부 포맷과 전체 통계

플로피 이미지 내부 구조는 다음과 같다.

~~~text
섹터 0–398       데이터 영역
섹터 399         디렉터리/섹터 맵
  0x63C00        4-byte 파일명 0x200 bytes
  0x63E00        섹터 맵 0x200 bytes
~~~

섹터 맵에서 map[0]과 map[395]는 0xFE 예약 표식이다. IPLD 디렉터리 항목은 특수 항목이며, 실제 파일 데이터는 디렉터리 인덱스 1부터 매핑된다.

53개 이미지를 모두 합산한 결과는 다음과 같다.

| 항목 | 수량 |
|---|---:|
| 디렉터리 항목 전체(IPLD 포함) | 1,735개 |
| 일반 파일(IPLD 제외) | 1,682개 |
| 타입 1 BASIC | 133개 |
| 타입 2 그래픽/이미지 | 1,184개 |
| 타입 3 기타 그래픽·데이터 | 365개 |
| 파일 선언 payload | 16,714,116 bytes |
| map상 할당 섹터 | 17,683개 |
| 헤더 기준 유효 섹터 | 17,098개 |
| map상 빈 슬롯 | 3,411개 |

타입별 로드 주소는 다음과 같다.

~~~text
type 1: 0x0000  133개
type 2: 0x3000  1153개, 0x4000 31개
type 3: 0x3000  364개, 0xD000 1개
~~~

타입 1은 e_scripts.csv의 105개 논리 스크립트와 일치한다. 나머지는 메인 디스크의 보조 BASIC 1개와 disk13–disk21에 존재하는 중복 BASIC 27개다.

일부 파일은 헤더가 선언한 섹터 수보다 map에 더 많은 섹터가 연결되어 있다. 전체적으로 585개 섹터가 이 상태이며, 이는 유효 payload와 별도로 남은 이전 데이터 또는 과할당 영역으로 보인다. 패치 시에는 map상 빈 슬롯과 파일 헤더의 실제 길이를 구분해야 한다.

map상 여유가 가장 적은 이미지:

~~~text
disk21  397 사용 / 1 빈 슬롯
disk52  397 사용 / 1 빈 슬롯
disk23  396 사용 / 2 빈 슬롯
main    393 사용 / 5 빈 슬롯
disk06  395 사용 / 3 빈 슬롯
disk40  395 사용 / 3 빈 슬롯
disk44  395 사용 / 3 빈 슬롯
~~~

원본 map을 정적으로 해석할 때는 디렉터리 인덱스를 직접 사용해야 한다. 현재 Ruby FloppyMan.rb의 map[i] == fCount 비교는 IPLD 특수 항목과 실제 원본 map의 인덱스 방식에 대해 한 칸 어긋나므로, 원본 이미지 추출·재패킹 전에 별도 검증이 필요하다.

## 6. 외부 D88 이미지 비교

외부 D88 세 파일은 각각 416,688 bytes다. 내부 구조는 모두 다음과 같다.

- D88 헤더: 0x2B0 bytes
- 80개 트랙: 실린더 0–39 × 헤드 0–1
- 트랙당 5개 섹터
- 섹터당 1024-byte payload와 16-byte D88 섹터 헤더
- payload 합계: 400 × 0x400 = 409,600 bytes

| D88 | CD 내장 이미지 비교 |
|---|---|
| Disk 1 - Main disk | main과 payload SHA-256 완전 동일 |
| Disk 2 - Game disk | disk01과 payload SHA-256 완전 동일 |
| Disk 3 - Save disk | Track 2 내장 이미지와 동일 해시 없음 |

## 7. Track 2의 예약·0 채움 영역

실제 MODE1 사용자 데이터에서 확인된 대형 연속 0 영역은 다음과 같다.

| 논리 오프셋 범위 | 크기 | 섹터 수 |
|---|---:|---:|
| 0x113F800–0x18AB7FF | 0x76C000 | 3,800 |
| 0x1C2F800–0x26ABFFF | 0xA7C800 | 5,369 |
| 합계 | 0x11E8800 | 9,169 |

합계는 18,778,112 bytes, 약 17.91 MiB다. 첫 번째 영역은 disk43과 disk44 사이이며, 두 번째 영역은 disk52 뒤쪽이다.

CSV에서 정의하지 않은 작은 구간도 존재하지만, 모두 곧바로 안전한 빈 공간으로 단정할 수는 없다. 다른 용도로 사용하기 전에 부트 로더·BASIC·ASM의 직접 참조를 확인해야 한다.

## 8. 영문 패치와의 관계

영문 배포 이미지와 원본은 음악 Track 3–15가 바이트 단위로 동일하고, 주요 변경은 Track 2와 Track 2 진입부에 집중된다. 영문 소스는 원본의 2D 이미지를 그대로 유지하지 않고, 런타임에 사용하는 논리 디스크를 여러 개의 2HD 이미지로 재패킹한다.

영문 소스의 기본 구조는 다음과 같다.

- VWF 출력 루틴 추가
- BASIC/ASM 영역 교체
- script/UI/menu 글꼴 뱅크 분리
- 시나리오 파일을 2HD 묶음으로 재패킹
- menu BASIC의 디스크 선택·복사 주소 수정

원본 물리 배치 53개와 영문판의 논리 2HD 재패킹 구조는 서로 다르다. 따라서 영문 소스의 CSV만으로 원본 CD 전체 배치를 판단하면 안 된다.

## 9. 분석 결론

1. 원본 CD는 ISO 파일시스템이 아니라 PC-8801 CD Type1 raw 데이터다.
2. Track 2 실제 논리 데이터는 40,550,400 bytes다.
3. raw MODE1 사용자 데이터 오프셋은 +16이다.
4. 원본 CD에는 main + disk01–disk52, 총 53개의 내장 2D 이미지가 있다.
5. 소스의 e_cddata.csv는 disk13–disk21 9개를 누락한다.
6. CD 뒤쪽에는 대형 연속 0-fill 영역이 존재한다.
7. 패치 전에 map 인덱스 방식과 map상 과할당 섹터를 도구에서 별도로 처리해야 한다.
8. 문서와 분석 도구의 기존 +24 계산식은 +16으로 수정되어야 한다.

이 문서의 분석은 정적 분석 결과이며, 에뮬레이터 실행이나 실제 게임 동작 검증은 포함하지 않는다.
