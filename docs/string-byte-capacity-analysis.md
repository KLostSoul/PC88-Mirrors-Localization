# 문자열 바이트 용량 비교 분석

이 문서는 일본 원문과 영문 패치의 문자열 저장 크기를 비교한 결과를 기록한다. 목적은 한글 2바이트 문자 토큰을 적용할 때 영문 패치의 문자열 영역이 실제로 얼마나 부족해질 수 있는지 판단하는 것이다.

에뮬레이터는 실행하지 않았으며, 다음 자료와 Ruby 원본 컴파일러 규칙만 사용한 정적 분석이다.

- korean_mirrors_tools/Export/Strings/stringsJapaneseEnglish.csv
- korean_mirrors_tools/Import/Data/script_widths.raw
- reference/mirrors_tools/Ruby/BasicCompiler.rb
- reference/mirrors_tools/Ruby/BasicDecompiler.rb

## 1. 계산 기준

### 1.1 일본어 원문

일본어 문자열은 원본 BASIC 문자열에 저장되는 Shift-JIS 바이트 수로 계산했다.

    일본어 문자열 레코드 = Shift-JIS 문자열 바이트 + 시작·종료 따옴표 2바이트

일본어의 전각 한자·가나·부호는 2바이트로 저장되지만, 원문에는 ASCII 숫자·영문·공백·드라이브 표기 등 1바이트 항목도 섞여 있다. 따라서 모든 문자를 단순히 문자 수×2로 계산하지 않고 실제 Shift-JIS 바이트를 사용했다.

분석 대상 일본어 문자열 중 Shift-JIS로 변환할 수 없는 행은 없었다.

### 1.2 영문 패치

영문 문자열은 단순히 영어 글자 수만 세지 않고 Ruby BasicCompiler.rb의 저장 경로를 반영했다.

- intro, menu: 문자열을 직접 저장
- 그 외 스크립트: script_widths.raw와 VWF 폭 제한 362를 사용해 줄바꿈
- BASIC 문자열 시작·종료 따옴표 포함
- 명시적 줄바꿈은 컴파일러의 연속 출력 규칙 반영
- em dash는 컴파일러 규칙대로 공백·하이픈·공백으로 치환
- 따옴표는 백틱으로 치환
- VWF 3줄 단위 분할 시 기존 제어 시퀀스와 따옴표를 추가

영문 문자열의 실제 패치 적용 상태도 반영했다.

- matched_translated: 영문 번역 바이트 계산
- matched_empty: 번역이 비어 있으므로 일본어 원문 바이트 유지
- patch_duplicate: 중복 패치 행도 실제 패치 입력으로 포함
- original_only: 영문 패치 입력에 없는 원문으로, 영문 교체 증감량에서는 제외

이 문서의 영문 값은 문자열 레코드 자체의 크기다. BASIC 줄 링크, 명령 토큰, 패치로 추가된 별도 BASIC 행까지 포함한 전체 파일 크기는 별도로 계산해야 한다.

## 2. 전체 결과

| 구분 | 행 수 | 일본어 레코드 | 영문 패치 레코드 | 증감 |

| 번역된 문자열 | 4,979 | 377,841 | 411,019 | +33,178 |
| 번역 공란·일본어 유지 | 299 | 16,324 | 16,324 | 0 |
| 중복 패치 문자열 | 4 | 262 | 282 | +20 |
| 영문 패치 대상 합계 | 5,282 | 394,427 | 427,625 | **+33,198** |

영문 패치 대상 문자열만 보면, 영문 패치의 문자열 레코드가 일본어 원문보다 총 33,198바이트 크다. 따라서 영문은 1바이트이므로 일본어보다 항상 작다는 가정은 실제 패치 데이터에는 적용되지 않는다. 영어 번역문이 일본어보다 길어진 구간과 VWF 줄바꿈 제어 바이트가 함께 작용한다.

번역된 4,979행의 개별 결과는 다음과 같다.

| 결과 | 행 수 |
|---|---:|
| 영문이 증가 | 2,550 |
| 영문이 감소 | 2,337 |
| 동일 | 92 |

중복 패치 4행까지 포함한 실제 번역 레코드 4,983행 기준으로는 증가 2,554행, 감소 2,334행, 동일 95행이다.

## 5. 한글 2바이트 토큰 적용에 대한 결론

아직 실제 한국어 번역문이 없으므로 한글판의 최종 바이트 수는 확정할 수 없다. 그러나 계산식은 다음과 같이 확정할 수 있다.

    한글 문자열 레코드
    = (표시 문자·부호 토큰 수 × 2)
      + 한글용 제어 바이트 수
      + 시작·종료 따옴표 및 BASIC 저장 오버헤드

일본어 원문도 전각 표시 문자는 대부분 2바이트이므로, 한글 토큰 자체가 일본어 원문보다 무조건 두 배로 커지는 구조는 아니다. 다만 영문 패치의 실제 번역 문자열은 일본어보다 이미 33,198바이트 크므로, 한글판은 다음 두 값을 모두 비교해야 한다.

1. 일본어 원문 대비 한글 토큰 문자열 크기
2. 영문 패치에 들어간 실제 BASIC 스크립트 영역 대비 한글 토큰 문자열 크기

따라서 영문 문자열을 일괄적으로 절반으로 줄이는 작업은 필요성이 확정되지 않았다. 실제 한국어 번역표가 완성되면 문자열별·스크립트별로 다시 계산하고, 초과하는 블록만 문장 축약 또는 분할한다.

## 6. 분석의 한계와 다음 검사

이번 결과는 문자열 레코드 단위의 정적 계산이다. 다음 항목은 한국어 번역 적용 후 별도로 확인해야 한다.

- 실제 한국어 토큰표에 따른 문자열별 바이트 수
- 한 BASIC 줄 전체의 명령 토큰·링크·패치 행 포함 크기
- 각 스크립트의 0x3000바이트 상한 초과 여부
- 문자열 분할 후 추가되는 VWF 제어 시퀀스
- Track 2의 BASIC 파일 삽입 영역과 실제 빈 공간

이 문서의 결론은 다음과 같다.

> 한글 2바이트 토큰의 적용 자체가 일본어 원문 대비 치명적인 용량 증가를 의미하지는 않는다. 하지만 영문 패치의 실제 번역 문자열은 일본어 기준으로 이미 33,198바이트 증가했으므로, 최종 한국어 번역문을 기준으로 스크립트별 재계산이 반드시 필요하다.
